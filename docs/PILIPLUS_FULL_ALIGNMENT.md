# PiliPlus 2.1.6 原生功能对齐

对照上游 `4ed5968f37af8b4aa7e0f13178cb8d8c2f86defc`（2026-10-06），原生起点为 `4ba12a39568523d9b281321a317f5ce078069449`。本轮按用户要求排除一起看、人像防挡、Chromecast。Android、Windows、Linux 特定实现不属于 Swift iOS/iPadOS 客户端的平台范围；相应业务功能仍需核对。

**当前为开发记录，不代表全量对齐完成。** 每项需要实际入口、协议处理、失败状态和验证证据。真实账号写入、付费内容和真实 DLNA/后台行为还需要用户后续验收，模拟器测试不替代这些结论。

## 内容与社交

首批实现：

- 动态发布/转发/编辑/置顶/取消置顶/删除；标题、图片、@、表情、话题、投票、仅自己可见、评论权限、定时发布。动态卡片长按进入管理，动态页右上角进入发布。
- 草稿按主账号分开，文本修改合并写入；图片独立保存，发布失败保留已上传图片地址。坏草稿需先备份后再新建，避免覆盖。
- 用户主页动态区搜索，支持上游页码与 offset 分页。
- 话题详情、排序、分页、折叠动态、收藏、点赞、参与讨论；动态投票详情与投票。图片投票/投票编辑、预约卡片等仍待补齐。
- 消息中心新增服务端 gRPC 全局设置、嵌套设置、关键词屏蔽；折叠会话分页及已有私聊页复用。需要有效 App access key，Cookie 登录不自动产生该凭据。
- 所有新写入请求仅尝试一次，避免网络重试重复发布/发送；操作绑定账号及凭据版本。不会为了测试向真实账号发布内容。

## 后续核验与实现

- 媒体：课堂课程播放与收藏、追番状态/合集订阅、游客字幕、高级弹幕及弹幕选中操作、AI 音轨、GIF/Live Photo、超分辨率、离线分组与 DLNA 队列。
- 基线逐项复核：`PILIPLUS_FEATURE_INVENTORY.md` 中未核验条目应按源码、入口、测试更新，不能因发现 API 名称就标记完成。
- 性能：Apple/Swift 官方规范调研、主线程与图片/磁盘热路径检查、可复现验证，保留真机 Instruments 待验证项。
