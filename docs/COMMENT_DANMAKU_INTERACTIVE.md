# 评论树、弹幕合并与复杂互动视频

2026-10-06 增量，基线为已合入 main 并发布的近期八项增强（`5737bd1` / `build-42-5737bd1`）。
本轮按用户确认实现三项；VideoTogether、Chromecast 不做，人像防挡不在本轮范围。

## 功能与入口

| 功能 | 使用方式 | 实现边界 |
| --- | --- | --- |
| 树状评论 | 视频、动态的楼中楼顶部选择「树状 / 平铺」；每个父回复可折叠、全部展开；布局偏好持久化 | 保留现有接口分页。缺失父回复用占位说明，后续页到达自动补齐；不会假称已读到未加载的内容 |
| 重复弹幕合并 | 播放器 → 弹幕设置 →「合并重复弹幕」，默认关闭 | 同一 15 秒视频时间窗口、同文及相同显示模式/颜色/字号合并为「内容 ×人数」；相同发送者去重，缺少作者时按弹幕 ID 区分。直播表情不参与 |
| 复杂互动视频 | 互动片段按作者时机显示选项；热点可以切换列表；播放器「互动分支」查看路径和继续保存的分支 | 条件、变量、默认/限时选择、自动节点、画面热点、结局、禁止回溯、变量快照与失败重试；普通视频继续走现有连播策略 |

评论树采用迭代建树和遍历，支持乱序分页、重复 ID、缺父与环，视觉缩进最多四层，实际父子关系和折叠仍完整保留。
评论写入、权限、账号与请求逻辑沿用现有实现。跳转评论时展开已加载的祖先节点。

弹幕保留原始文本，计数只用于绘制。XML、分段 protobuf 和离线索引保留作者哈希；旧离线索引仍可读取。
修改合并开关会立即重建渲染窗口，包含完整时间桶，避免移动窗口时人数变动。

## 互动视频状态

- 从 `graph_version` / `edgeinfo_v2` 读取完整问题数组、条件、动作、变量和视频尺寸。
- 受限 Swift 表达式支持算术、比较、逻辑短路、括号和多条赋值；不执行服务端脚本，限制输入长度、变量数、递归深度与自动分支循环。
- 随机变量保留第一次服务端值；作者要求不覆盖的变量、已经执行动作写入的变量均保留。旧、新变量名同步。
- 切换前检查目标播放地址，等待目标画面出现后才提交变量和路径。失败保留原剧情快照，必要时恢复原片段和播放进度；重试不会重复增加变量。
- 路径保存完整变量与访问标识，同一节点重复访问仍可区分。按播放账号、视频、图版本分开保存；账号或导航上下文改变后丢弃旧请求结果。
- 回溯成功才截断路径；禁止回溯标志随路径保留。旧存档缺少变量且目标需要变量时提示重开，避免恢复出错误剧情。
- 倒计时在页面非活跃或应用后台时停止；到期只使用满足条件的默认选项。自动节点在片段结束后切换，互动结局不触发普通相关推荐连播。
- 定时停止优先于倒计时默认选择和自动分支；等待分支信息或播放地址期间到点也不会自动继续。用户明确点击重试、选项或重新开始后才恢复。
- 像素热点按视频宽高和底部坐标原点映射到画面；缺尺寸、旋转元数据或无效坐标时提供列表。支持显式重新开始。

参考上游开放 PR [#2927](https://github.com/bggRGjQaUbCoE/PiliPlus/pull/2927)、[#2476](https://github.com/bggRGjQaUbCoE/PiliPlus/pull/2476)、[#3172](https://github.com/bggRGjQaUbCoE/PiliPlus/pull/3172) 的业务规则，采用独立 Swift 实现；不是将 Flutter 补丁直接合并进原生仓库。

## 验证

- `PiliPlaybackCore`：树/深层与环、时间窗口/发送者去重、表达式/变量/热点/循环防护，Linux Swift 6.2.3 共 33 项通过。
- iOS 增加 XML/protobuf/离线兼容、真实弹幕 UILabel 切换合并、互动网络失败/播放失败/重试/账号切换/变量回溯/限时选择/存档与作者限制测试。
- UI 增加树折叠/分页/布局持久化、互动条件选项/热点点击/变量回溯/结局与重新开始。测试使用生产组件和控制器，以确定性离线数据替代网络。
- `Scripts/test-ios.sh` 运行完整 iOS 单元测试及四个玻璃 UI 场景；`Scripts/capture-preview.sh` 增加 `preview-comment-tree.png` 和 `preview-interactive.png`。
- 本文初次提交时 iOS 增量仍在 CI 验证；最终成功记录以同版本 Actions 与 Release 为准。

模拟器测试无需签名。真实账号、互动视频的服务端特殊规则、不同设备画面缩放、长列表滚动及实机性能仍需用户后续反馈。
UI 样例截图只证明生产组件的确定性场景，不代表已经完成所有线上内容验收。

## 是否已经与原版完全对齐

没有。这三项包含上游尚未合并的扩展，完成它们不能替代其余原版模块的迁移。
截至本轮源码审计，主要缺口仍包括：

1. 动态发布/编辑/管理、投票话题与完整草稿；消息全局设置、折叠会话和内容卡片发送。
2. PUGV 课堂、追番状态与合集订阅管理；专栏原生正文与文章互动。
3. 评论热度/时间切换及翻译；弹幕悬停操作、高级模式与特殊交互。
4. 未登录字幕兜底、PiP 字幕；笔记富文本、图片和时间标签。
5. 整合集离线归组、DLNA 队列及更多媒体/网络类型；后台与电视兼容性验收。
6. 手动 Cookie 登录、用户动态搜索和完整 @ 选择；截图/GIF/Live Photo 等媒体工具。
7. 剩余消息、直播、离线与表单页面的液态玻璃统一，以及无障碍、真机播放和长时间稳定性验证。

具体基线和上游事项初筛见 [功能清单](FEATURE_PARITY.md) 与 [开放事项评估](UPSTREAM_OPEN_WORK_2026-10-05.md)。
直播弹幕解压预算等此前独立排期的可靠性工作也未计入本轮三项。
